# 配置说明

> JianShanAgent · 核心 · 文档

有哪些配置文件、每份管什么、常改的是哪几项、改了怎么生效。每一项的含义写在默认配置文件的注释里（管理后台「机器人配置」页显示的就是这些注释），这里只做索引。

## 配置写在哪

默认值随代码走，你只写和默认值不一样的地方。要改哪份配置，就在实例的 `config/` 下建一个和它同名的文件，只写要改的那几项：

```yaml
# config/plugin.research.yaml
answer_chars: 500        # 别的项不用抄过来，照默认值
```

一共五层，后面的盖住前面的：

| 层 | 在哪 | 谁来写 |
|---|---|---|
| 默认值 | 核心的 `src/jianshanagent/defaults/*.yaml`、各插件目录里的 `config.yaml` | 随代码走，不用动 |
| 平台和站点插件的补充 | 平台（核心的 `platforms/<id>/`）和站点插件 `config.yaml` 的 `extend` 段，平台的先并。只对用它的那个 wiki 生效 | 核心、写站点插件的人 |
| 这个部署的改动 | 实例的 `config/<配置名>.yaml` | 你 |
| 本机调试 | 实例的 `config/local/<配置名>.yaml`（不入库） | 你，只在开发机上 |
| 管理后台里改的 | `data/config/<配置名>.yaml`（容器里是 `/data/config/`） | 后台自动写，删掉文件就恢复默认 |

字典逐层合并，列表和单个值整个替换。凭据单独放在 `config/secrets.yaml`，不在这几层里。

挂了几个 wiki 时，每个 wiki 各有一份配置：通用的配置加上它的平台和站点插件的补充。取数、清洗、查询读的是各自那一份；对话、查证、记忆、人设只有一份，用的是主 wiki（`wikis` 里排第一的）的。管理后台里看到、改的是主 wiki 的那一份，改动对每个 wiki 都生效——站点插件补过的名单（比如清洗规则），只把「加了哪些、去了哪些」用到别的 wiki 上。

## 配置文件一览

「生效」一栏：**马上** = 在管理后台保存后不重启就生效；**重启** = 要重启机器人；**发布** = 不能在后台改，要改文件再重新启动或发布。

### 全局和接入

| 配置名 | 管什么 | 常改的项 | 生效 |
|---|---|---|---|
| `app` | 日志、HTTP 端口 | `log.level`、`log.json`；`healthcheck.host` / `port`（管理后台也在这个端口，默认 `0.0.0.0:8080`） | 重启；端口只能改文件 |
| `gateway.qq` | QQ 接入 | `enabled`（关掉就不连 QQ，后台照常能用）；`reply.passive` 一条消息最多回几次；`shutdown.drain_seconds` 退出前等在途消息多久 | 重启 |
| `core.wiki` | 服务哪些 wiki | `name`、`about`；`wikis` 名单，一项一个 wiki：`id`、`label`（标出处时的叫法）、`api_url`、`site_base`、`article_path`、`auth_header`、`site`（用哪个站点插件）、`platform`（没有站点插件的 wiki 在哪个平台上）。排第一的是主 wiki。可以一个都不写，在管理后台的「Wiki」页里添加 | 发布；后台加的马上 |
| `core.plugins` | 启用哪些功能插件、按什么顺序 | `enabled` | 马上 |
| `core.router` | 命令前缀、限流 | `command_prefixes`；`rate_limit.per_user_per_minute` / `per_group_per_minute` | 马上 |

### 模型和存储

| 配置名 | 管什么 | 常改的项 | 生效 |
|---|---|---|---|
| `core.llm` | 对话模型 | `base_url`（只能改文件）；`profiles` 各档用哪个模型、开不开思考、最多出多少 token；`history.max_turns` 带几轮上文 | 马上 |
| `core.embedding` | 嵌入（算向量） | `default_provider`；`providers.<名字>` 的地址、型号、维度、并发 | 马上 |
| `core.websearch` | 联网搜索（只有查证的 `web` 那一级用） | `enabled`（默认关）；`provider` 用哪一家（`mimo` / `gitee_ai`）；`count`；`providers.mimo` 的 `model`、`force_search`；各家的地址和密钥名只能改文件 | 马上 |
| `core.update` | 核心的更新 | `enabled`（查不查新版本）；`check_interval_hours`；`repo`、`api_url`、`download_prefix` 只能改文件 | 马上 |
| `core.catalog` | 站点目录：管理后台的「Wiki」页从哪里列做好了的站点插件、从哪里下载 | `enabled`；`cache_minutes`；`repo`、`path`、`ref`、`api_url`、`download_prefix` 只能改文件 | 马上 |
| `core.storage` | 数据库连接池 | `postgres.pool_min` / `pool_max` | 重启 |
| `core.trace` | 处理记录留多久 | `prompts.keep`、`prompts.retention_days`、`retention_days` | 马上 |
| `core.admin` | 管理后台 | `session_days`、`login` 输错几次锁多久、`backup_warn_hours`、`logs_url`；`enabled` 和 `token_file` 只能改文件 | 重启 |

`core.llm` 的档位：`chat` 是面向用户的对话入口，`quick` 是查证工作流里分析问题、写结论、复核用的，`extract` 是后台抽取（记忆）用的，`reason`、`review` 是带思考的备用档。查证工作流的哪个角色用哪一档，在 `plugin.research` 的 `profiles` 里（管理后台「模型管理」页能直接改）。

### 功能插件

| 配置名 | 管什么 | 常改的项 |
|---|---|---|
| `plugin.safety` | 发出去的消息过一遍检查 | `outbound.max_message_chars`、`outbound.block_patterns` |
| `plugin.wiki_query` | `/查` | `commands.lookup` 的命令名和别名；`wiki.search_ranking`；`format.max_chars`（几个 wiki 都有这个条目时每个 wiki 各这么多字）、`format.markdown`、`format.knowledge_fallback` |
| `plugin.knowledge` | 知识库 | `paths.root` 知识库目录（下面一个 wiki 一层）；`retrieval.top_k`；`images.min_score`；`fetch` 对 wiki 的限速（别调高）；`sync` 自动更新的间隔、全部重取的时段、闸门；`clean.remove_classes` 清洗规则；`chunk` 切片大小 |
| `plugin.research` | 查证工作流 | `profiles`；`deadline_seconds`；`stages` 先查哪里后查哪里；`answer_chars` 回答多长；`max_citations`；`max_rejections` 复核最多打回几次；`progress` 进度提示的文案；`wording` 提示词里的说法 |
| `plugin.chat` | 对话 | `prompts`；`entry_timeout_seconds`；`images.max_per_message`；`persona` 用哪张人设；`commands.reset` |
| `plugin.memory` | 记忆 | `max_items`、`max_chars`；`scope` 群聊和单聊各记什么；`commands` |
| `plugin.chatlog` | 群聊记录 | `scopes`、`keep_days` |
| `persona/persona.default` | 人设 | `name`、`description`、`personality`、`system_prompt` |

这些都是保存后马上生效。平台的配置叫 `platform.<id>`（`platform.huiji`、`platform.bwiki`），站点插件的叫 `site.<id>`（例如 `site.huiji_yys`），也在后台的「机器人配置」页里；其中的 `extend` 段不能在后台改。

### 在管理后台里添加的 wiki

「Wiki」页里从站点目录添加的 wiki 不写进实例的 `config/core.wiki.yaml`，存在覆写目录的 `core.wiki.yaml` 里（`wikis_added`，容器里是 `/data/config/core.wiki.yaml`）。读配置时接在部署写的 `wikis` 后面，所以「机器人配置」页里看到的是合在一起的一张只读名单。哪一项挂不上（站点插件没了、id 和部署写的重了）就跳过那一项，原因显示在「Wiki」页里，别的照常。下载的站点插件在 `data/sites/`。

## 不能在管理后台改的项

登录了后台的人不应该能拿到凭据，也不应该能让机器人去加载别的代码，所以这些只能改文件：

- 所有的接口地址和「用哪个密钥」：键名是 `base_url`、`api_url`、`site_base`、`auth_header`、`secret`、`dsn_env`、`url_env`、`token_file` 的项；
- `core.wiki` 的 `wikis`（挂哪些 wiki、各自的地址和站点插件）、平台和站点插件配置里的 `extend`。「Wiki」页里只能从站点目录添加：地址和用哪个站点插件照目录里写的，网页上只能起名字；
- `core.update` 的 `repo` 和 `download_prefix`（从哪里下载新版本）；
- `core.catalog` 的 `repo`、`path`、`ref`、`download_prefix`（站点目录在哪、站点插件从哪里下载）；
- `core.admin` 的 `enabled`、`app` 的 `healthcheck`（改错了会把后台自己关在外面）。

## 凭据

`config/secrets.yaml`，从 `config/secrets.example.yaml` 复制后填写，不入库。写着 `YOUR_` 开头的占位值算没填。

| 键 | 是什么 | 不填会怎样 |
|---|---|---|
| `qq.app_id`、`qq.client_secret` | QQ 开放平台机器人的凭据 | 连不上 QQ；只用网页对话时可以不填（带 `JIANSHANAGENT_DRY_RUN=1` 启动） |
| `llm.api_key` | 对话模型的密钥 | 启动报错，明说缺这一项 |
| `gitee_ai.api_key` | 嵌入接口的密钥（默认用模力方舟）；联网搜索选 `gitee_ai` 时也用它 | 检索只走关键词，不能以图搜图，也算不了新的向量 |
| `mimo_search.api_key` | 联网搜索的密钥：小米 MiMo 按量付费的那种（`sk-` 开头），账号要开通「联网服务插件」。只有联网搜索用它，和 `llm.api_key` 不通用 | 没有联网搜索，查证只查知识库和站内 |
| `postgres.dsn` | 数据库连接串 | 对话历史、记忆、处理记录只放内存，重启就没了；知识库、查证工作流、群聊记录不生效 |
| `wiki.<id>.authkey`、`wiki.<id>.cookie` | 那个 wiki 要带放行请求头时的密钥（`<id>` 是 `core.wiki` 的 `wikis` 里它的 id，请求头名是它的 `auth_header`） | 不需要放行的站不用填 |
| `admin.token` | 管理后台的登录令牌，至少 12 个字符 | 第一次启动自动生成一个，存在 `data/admin/token` |

## 环境变量

| 变量 | 作用 |
|---|---|
| `JIANSHANAGENT_DRY_RUN=1` | 不连 QQ，只开管理后台和网页对话 |
| `JIANSHANAGENT_CONFIG_DIR` | 配置目录；不设就用当前目录下的 `config/` |
| `JIANSHANAGENT_CONFIG_OVERRIDES_DIR` | 管理后台改的配置存在哪；不设就是配置目录旁边的 `data/config`，设成空的 = 不让后台改配置 |
| `JIANSHANAGENT_POSTGRES_DSN` | 数据库连接串，优先于 `secrets.yaml` 里写的 |
| `JIANSHANAGENT_LLM_API_KEY` | 对话模型的密钥，优先于 `secrets.yaml` 里写的 |
| `QQ_BOT_APP_ID`、`QQ_BOT_CLIENT_SECRET` | QQ 凭据，`secrets.yaml` 里没填时用它们 |
| `JIANSHANAGENT_KB_DIR` | 知识库目录（下面一个 wiki 一层）；不设就是 `plugin.knowledge` 的 `paths.root`（默认 `data/kb`） |
| `JIANSHANAGENT_UPDATE_DIR` | 在后台点「更新」装的新版本放在哪；不设就是实例目录的 `data/core` |
| `JIANSHANAGENT_SITES_DIR` | 在后台的「Wiki」页里下载的站点插件放在哪；不设就是实例目录的 `data/sites` |
| `JIANSHANAGENT_ADMIN_TOKEN_FILE` | 登录令牌文件的位置，优先于 `core.admin` 的 `token_file` |
| `JIANSHANAGENT_SESSION_STORE_DIR` | QQ 连接会话存在哪，优先于 `gateway.qq` 的 `session_store_dir` |
| `JIANSHANAGENT_LOG_JSON=1` | 日志打成 JSON（给日志采集用），优先于 `app` 的 `log.json` |

容器里这几个路径都指到挂载的数据目录 `/data` 下，compose 文件里已经设好了。
