# 架构

> JianShanAgent · 核心 · 文档

JianShanAgent 是挂在 QQ 上的 wiki 问答机器人。核心只懂 MediaWiki 和 QQ；某个平台、某个站特有的东西由插件带进来。这份文档说核心里有什么、一条消息怎么走、数据放在哪。插件怎么写见 [插件规范](插件规范.md)，怎么部署见 [部署与运维](部署与运维.md)。

## 组成

| 部分 | 在哪 | 管什么 |
|---|---|---|
| 网关 | `gateway/qq.py` | 和 QQ 开放平台的长连接（`qqbot-agent-sdk`）：收消息、发回复、断线续接 |
| 路由 | `core/router.py` | 限流、认命令、把消息交给对的插件；出站的消息统一过一遍检查 |
| 插件宿主 | `core/plugin.py`、`core/manifest.py`、`core/sites.py` | 找到插件、按清单装上；功能插件开扩展点，站点插件往里接 |
| 配置 | `core/config.py`、`defaults/` | 分层读配置：默认值 → 站点插件的补充 → 部署的改动 → 管理后台里改的 |
| 模型调用 | `core/llm.py`、`core/embedding.py`、`core/websearch.py` | 对话模型、嵌入（文字和图片同一个向量空间）、联网搜索，都是 OpenAI 兼容的 HTTP 接口 |
| 存储 | `core/db.py`、`migrations/` | Postgres 连接池；数据库结构的变更在启动时按文件名顺序执行 |
| 处理记录 | `core/trace.py`、`core/trace_store.py` | 每条消息走了哪几步、各步多久、调了几次模型，记进库里 |
| 管理后台 | `admin/`（接口）、`webui/`（页面） | 挂在机器人自己的 HTTP 服务上，和健康检查同一个端口 |
| 装配 | `runtime.py`、`main.py` | 读配置 → 连数据库 → 装模型、插件、路由 → 起 HTTP → 连 QQ |

## 一条消息怎么走

1. **进来**：网关把 QQ 的事件整理成统一的消息（谁、在哪个群或私聊、说了什么、带了什么图）。
2. **路由**：先限流。以命令前缀（`/`、`！`、`!`）开头的按命令走——`/查` 这类命令直接查 wiki，不过模型。群聊记录这类「旁听」的插件每条消息都看得到，但不回复。
3. **对话**：没有命中命令的消息交给对话插件。闲聊由对话模型直接回；涉及 wiki 内容的问题，模型调用查证工作流。
4. **查证**：分析问题（认出里面的名字、别名）→ 逐级取证（知识库检索、站内搜索，可选联网搜索；带图的消息先以图搜图）→ 写结论 → 复核，不过关就打回重写 → 结论连同参考资料直接发给用户。每到一个阶段给用户发一句进度。
5. **出去**：所有要发的消息（包括进度）过安全兜底（长度、不该发的内容）和链接核对（模型写的链接只留确实查到过的），再由网关发回 QQ。

## 插件

三种，按「谁的事」分层，规矩见 [插件规范](插件规范.md)：

- **功能插件**——机器人会做的事。核心自带七个：

  | id | 名字 | 管什么 |
  |---|---|---|
  | `safety` | 安全兜底 | 发出去的消息过一遍检查，拦下不该发的 |
  | `wiki_query` | wiki 查询 | `/查` 和给模型用的查询工具：按标题找页面、全文搜索、取摘要。开出扩展点 `wiki` |
  | `knowledge` | 知识库 | 把 wiki 取下来清洗、切片、算向量、入库，供检索和以图搜图；按最近更改自动更新。开出扩展点 `knowledge` |
  | `research` | 查证工作流 | 分析问题 → 取证 → 写结论 → 复核 |
  | `memory` | 记忆 | 记住用户明说要记的事；用户可以查看和清除 |
  | `chat` | 对话 | 没有命中命令的消息走这里；人设在它的 `configs/persona/` 里 |
  | `chatlog` | 群聊记录 | 把群里的消息和机器人的回复记进数据库 |

- **站点插件**——某个 wiki 平台、某个站特有的东西，接在 `wiki`、`knowledge` 两个扩展点上，或者用 `extend` 补充通用配置。核心不带站点插件。
- **部署插件**——和机器人一起部署、机器人离了它照样跑的服务。核心带一个：`logs`（运行日志）。

## 知识库

`knowledge` 插件把 wiki 变成可以检索的资料：

1. **取数**：列出页面，取渲染后的内容；按修订号缓存，没变的不重取。对 wiki 限速、限并发。
2. **清洗和切片**：去掉导航、模板噪声，把页面按标题和长度切成片；每片带着出处。清洗规则是配置，站点插件可以补。
3. **算向量、入库**：切片和图片用同一个嵌入模型算向量，存进 Postgres（pgvector）。
4. **检索**：向量检索加关键词，供查证工作流用；以图搜图在图库的向量里找最像的。
5. **自动更新**（`kbsync` 服务）：定时读 wiki 的最近更改，只重做变了的部分；说不清影响哪些页面的改动，夜里把渲染的页面全部重取一遍兜底。没人盯着，所以每一步都有闸门，不对劲就停下来等人看。

站点插件可以往里接自己的内容：别的来源的文档、实体标注、图库选图、哪些改动影响哪些页面。

## 数据

| 放在哪 | 是什么 |
|---|---|
| Postgres | 对话历史、记忆、知识库的切片和向量、图库、群聊记录、处理记录和模型调用、管理后台的标注、备份记录 |
| 数据盘 `/data/kb` | 知识库的文件：切片、向量、取数缓存、自动更新读到哪里了 |
| 数据盘 `/data/config` | 管理后台里改过的配置（只记和默认值不一样的项） |
| 数据盘 `/data/admin`、`/data/qq_ws` | 管理后台的登录令牌；QQ 连接的会话（重启后续接用） |

凭据不进镜像、不进数据库，运行时单独挂进来。

## 进程

一个镜像，两个入口：

| 服务 | 入口 | 说明 |
|---|---|---|
| `qqbot` | `jianshanagent` | 机器人。HTTP 端口上同时是健康检查和管理后台 |
| `kbsync` | `python -m jianshanagent.plugins.knowledge sync --loop` | 知识库自动更新。单独一个进程：重算切片占 CPU 和内存，不能卡住收发消息 |

另外是 Postgres、每日备份、Redis（预留，现在的代码不用它），和部署插件带来的服务。

## 外部依赖

| 是什么 | 怎么接 | 配置 |
|---|---|---|
| QQ 开放平台 | `qqbot-agent-sdk` | `gateway.qq`；凭据 `qq.app_id` / `qq.client_secret` |
| MediaWiki | 站点的 `api.php` | `core.wiki` |
| 对话模型 | OpenAI 兼容的 Chat Completions | `core.llm` |
| 嵌入模型 | OpenAI 兼容的 `/embeddings`，文字和图片都能算 | `core.embedding` |
| 联网搜索 | 可选，默认关 | `core.websearch` |

## 写代码时要知道的约束

- **同一个机器人不能两处同时在线**，不然一条消息会被回复两次。本机调试用 `JIANSHANAGENT_DRY_RUN=1`（不连 QQ）。入口命令 `jianshanagent` 没有 `--help`，一运行就是启动。
- **`qqbot-agent-sdk`**：要先 `api.setup(httpx.AsyncClient())`，不然取网关地址和发消息都报`HTTP client not initialized`；停止用 `await ws.async_stop()`。
- **QQ 的被动回复有次数上限**（`gateway.qq` 的 `reply.passive`），进度消息也占名额；回复里带了平台不认的链接，整条消息会被拒。
- **思考模式的对话模型**：历史里带工具调用的那几条，要把模型当时的思考内容原样带回去，所以对话历史落库而不只放内存。
- **对 wiki 取数要守规矩**：那是别人的生产站点。限速和并发在 `plugin.knowledge` 的 `fetch` 里，别调高。
- **日志只往标准输出打 JSON**，谁来收是部署插件的事；问题的内容、搜索词不进日志。
